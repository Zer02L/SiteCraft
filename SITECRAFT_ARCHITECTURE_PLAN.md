# 📐 Архитектурный план: Универсальный конструктор сайтов (SiteCraft Starter Kit)

Данный документ представляет собой согласованную архитектурную спецификацию и технический план создания универсального стартового набора (Starter Kit / Boilerplate) на стеке **Go 1.27 + PocketBase + Templ + HTMX + Tailwind CSS**.

План составлен с учетом разрешения потенциальных конфликтов сборки, производительности базы данных SQLite, модульности клиентского JS и изоляции схем данных.

---

## 1. Стек и архитектурные принципы

1. **Единый бинарник (Single Binary):** Сервер, SQLite-база, панель управления (`/_/`), шаблоны и ассеты компилируются в один легковесный файл (~25–35 МБ).
2. **Нулевой рантайм Node.js в продакшене:** Стили и шаблоны компилируются заранее; серверу для работы не нужны внешние интерпретаторы.
3. **Zero-JS фундамент (Progressive Enhancement):** Базовый сайт функционирует полностью без клиентского JS (с использованием нативных возможностей HTML5 и HTMX для сетевых запросов).
4. **Сверхнизкое потребление ресурсов:** Потребление оперативной памяти 20–40 МБ RAM, что позволяет размещать десятки клиентских сайтов на одном сервере за 5$.
5. **Мгновенный TTFB (<10 мс):** Строго типизированный серверный рендеринг через Templ в связке с in-memory кэшированием неизменяемых данных.

---

## 2. Разрешение архитектурных конфликтов и ограничения

Перед началом реализации зафиксированы решения для 5 ключевых узких мест:

### 2.1. Конфликт: Tailwind Tree-Shaking vs Динамические темы
* **Проблема:** Tailwind отслеживает классы на этапе компиляции. Динамические цвета из базы данных не попадут в CSS.
* **Решение:** В шаблонах используются исключительно **семантические токены** (`bg-primary`, `text-accent`, `bg-surface`, `text-main`). Физические цвета привязываются в `input.css` через CSS-переменные:
  ```css
  [data-theme="medical"] {
      --color-primary: 13 148 136;
      --color-accent: 14 165 233;
      --color-surface: 240 253 250;
  }
  ```
  В `tailwind.config.js` цвета определяются через `rgb(var(--color-primary) / <alpha-value>)`. Это обеспечивает 100% стабильность CSS-файла.

### 2.2. Конфликт: Опциональный Alpine.js vs Модуль Доступности (a11y)
* **Проблема:** Текущая панель для слабовидящих завязана на Alpine.js. Если отключить Alpine, панель сломается.
* **Решение:** Панель a11y реализуется на **нативном Vanilla JS (микро-скрипт < 1 КБ)** с переключением классов на `<html>` и записью в `localStorage`. Это исключает жесткую зависимость от Alpine.js.

### 2.3. Конфликт: Схема БД SQLite vs Разные типы заявок
* **Проблема:** У юриста заявка требует `booking_date` и `booking_time`, у автосервиса — `car_model` и `vin`, у оптовика — `company_name`.
* **Решение:** Таблица `leads` разделяется на базовые и расширенные поля:
  * Базовые (фиксированные): `name`, `phone`, `email`, `status`, `source`, `created`.
  * Динамические (JSON): поле `payload` (JSON-объект), куда сохраняются любые специфичные для ниши поля без миграции колонок базы.

### 2.4. Конфликт: Нагрузка на SQLite при множественных фиче-тогглах
* **Проблема:** Проверка 8+ настроек (`theme`, `map_mode`, `booking_mode`, счетчики) на каждый HTTP-запрос снижает пропускную способность.
* **Решение:** Внедрение **In-Memory Cache (sync.RWMutex)** в Go:
  * Настройки сайта и услуги хранятся в оперативной памяти сервера.
  * Инвалидация происходит по событию PocketBase: `app.OnRecordAfterUpdateSuccess()`.
  * Чтение настроек на запрос: **0 мс (O(1) в RAM)**.

### 2.5. Конфликт: Жизненный цикл пресетов ниш
* **Проблема:** Попытка менять бизнес-пресет на лету в работающем сайте приводит к коллизиям контента.
* **Решение:** Пресет (Юрист, Клиника, Автосервис) применяется **один раз на этапе инициализации проекта** через CLI/скрипт сидирования. После этого проект развивается независимо через админку.

## 3. Модульная структура ядра

```
.
├── cmd/
│   └── sitecraft/        # Точка входа приложения
├── internal/
│   ├── app/              # Инициализация PocketBase и роутов
│   ├── cache/            # In-memory кэш настроек сайта
│   ├── config/           # Глобальные параметры окружения
│   ├── data/             # Схема БД, сидеры пресетов (presets/)
│   ├── handlers/         # Обработчики HTTP и валидация HTMX-форм
│   └── notifications/    # Telegram Bot, Webhooks (amoCRM/Битрикс24), Email
├── presets/              # Готовые JSON-файлы для ниш (legal, medical, auto, beauty)
├── ui/
│   ├── assets/           # Стили (Tailwind, темы CSS)
│   ├── components/       # Библиотека переиспользуемых Templ-блоков
│   │   ├── hero/         # Варианты первого экрана
│   │   ├── services/     # Каталоги, прайсы, карточки
│   │   ├── booking/      # Формы захвата (слоты / простая / квиз)
│   │   ├── trust/        # Отзывы, FAQ, счетчики, контакты
│   │   └── common/       # Навбар, футер, модалки, a11y-панель
│   └── layouts/          # base.templ (управление скриптами, data-theme)
```

## 4. Каталог опциональных подсистем (Feature Toggles)

Все подсистемы управляются тумблерами в админке (`site_settings`) или флагами инициализации:

| Модуль | Поведение по умолчанию | Опциональное поведение | Управление |
|---|---|---|---|
| **Alpine.js** | Отключен (Zero-JS) | Включен (для калькуляторов, масок ввода) | `enable_alpine_js` (bool) |
| **Доступность (a11y)** | Отключен | Включен (Vanilla JS панель контраста и шрифтов) | `enable_a11y` (bool) |
| **Форма захвата** | Простая (Имя + Телефон) | Сетка слотов календаря / Квиз в 3 шага | `booking_mode` (enum) |
| **Карта** | Статичная картинка (100 PageSpeed) | Интерактивный виджет с ленивой загрузкой | `map_mode` (enum) |
| **Антиспам** | Honeypot (Zero-JS, всегда активен) | Cloudflare Turnstile капча | `enable_turnstile` (bool) |
| **Аналитика** | Отключена | Подключение Метрики / GA4 / VK Pixel | `yandex_metrika_id` (string) |
| **Поиск** | Отключен | Полнотекстовый поиск SQLite FTS5 через HTMX | `enable_search` (bool) |
| **Уведомления** | Только сохранение в админку | Пуш в Telegram с кнопками + CRM Webhook | `telegram_bot_token` (string) |
